### 💡 نبذة عن أهم الخصائص البرمجية المدمجة بالتطوير الأخير:

1. **الفرز اللغوي الجغرافي**: داخل `WilayasList.tsx` والتبويبات المقترنة، يتم ترجمة العبارات ومطابقة مدخلات الزبون العشوائية (مثل: *وهرن, Oran, Ohran*) وتركيزها مباشرة على الكود الإداري الصحيح المقترن في الـ 58 ولاية جزائرية ومستودعات البلديات.
2. **التصفية المتشعبة الفورية (Stats Drilling)**: داخل `Dashboard.tsx` بلمسة زر على أي مؤشر مبيعات تظهر قائمة فلترة تامة تمسح وتتابع تفاصيل المتسوقين والطلبات المرتبطة بتلك الإحصائية دون مغادرة الواجهة.
3. **تتبع المرتجعات التفاعلي**: نظام تتبع لوجستي متقدم يتتبع ويقيس خسائر المرتجعات ويرشح للمستخدمين تأكيد الطلبيات هاتفياً للولايات التي تسجل مستويات مرتفعة من الطرود غير المستلمة.
4. **التأكيد الإداري والمالي الفوري**: دعم باقات الاشتراكات عبر بوابة الدفع الوطنية الأكثر شهرة في الجزائر **Chargily Pay V2** لتفعيل ومراقبة الفواتير في بيئة الـ Sandbox الفورية، مع بقاء نظام CCP والتحقق المباشر من إيصالات المصرفية بصلاحية المسؤول (Admin) مع المعاينة الصورية.
5. **لوحة المنتجات والمتاجر الرقمية المستقلة (Storefront Ecosystem)**: إطلاق فوري لنظام متجر كامل لكل تاجر لتمكينه من نشر رابط متجره (بالمسار `/store/:merchantId/info`) وتلقي الطلبات من الزبائن النهائيين بشكل مؤتمت وتخزين المبيعات فورياً في قاعدة البيانات وتحديث جدول المخازن.
6. **الاعتماد الكلي على SDK Gemini الرسمي مع معالج الرجوع التلقائي المتين للنماذج**: تم استبدال مكالمات الذكاء الاصطناعي بنظام متين جداً في `server.ts` يحمل اسم `generateContentWithRetry`؛ حيث يقوم بتجربة استدعاء نموذج `gemini-2.5-flash` أو `gemini-3.5-flash` مع معالجة الاكتظاظ أو الحظر المؤقت، وفي حالة مواجهة خطأ 503 أو 429، يتم التراجع الأوتوماتيكي والنسخ الاحتياطي بين النماذج (`gemini-1.5-flash` و `gemini-2.5-pro` وغيرهما) مع تفعيل نظام مضاعفة وقت التأخير الأسي (Exponential Backoff) لضمان عدم توقف عمليات استخلاص الطلبات إطلاقاً.
7. **الاتصال بالخوادم المزدوجة لـ Firebase (Dual-Mode Cloud Engine)**: تم ترميم `src/lib/firebase.ts` ليتمكن المطور محلياً من شحن متغيرات البيئة عبر المنافذ الافتراضية بسهولة قصوى وتخطي أي عوائق في المزامنة أو التشغيل الآمن محلياً وسحابياً.
8. **نظام رصد وحماية التوجيه التلقائي (Anti-Stall & Redirection Watchdog)**: يتضمن التطبيق آلية مراقبة أمنية ذكية في `App.tsx` عند تحميل المعرفات (Auth Loading watchdog) لرصد أي تعليق أو عجز عن التوجيه من صفحة الهبوط في نوافذ المعاينة المؤطرة المدمجة (Sandbox iFrames)، مع توفير شريط تنبيهي ديناميكي ينصح المستخدم عند تأخر استجابة سحابة Firestore ويوجهه لفتح التطبيق في نافذة مستقلة وتفادي قيود الكوكيز التابعة للمتصفح.
9. **التحكم وحجب الأخطاء التقنية وحصرها في الـ Console**: تم تعديل كافة معالجات الأخطاء وعمليات التفتيش وأقنية التحقق (خاصة أخطاء الـ Google Auth/Firestore/Chargily API) لتمنع حدوث فرقعات (popups) أو تنبيهات نصية فنية مزعجة للزبون النهائي؛ حيث يتم تقديم كافة الأخطاء التقنية بدقة إلى كونسول فحص المتصفح (`console.error` و `console.warn`) للأغراض التطويرية الأمنية والتشخيصية، مع التعبير عنها للمستخدم برسائل جذابة وصديقة تفيد بحدوث خلل عام مبسط وتطلب مراجعة الكونسول.
10. **رصد الشبكة وجودة المزامنة**: إدماج مكون `NetworkStatus.tsx` لرصد حالة الإنترنت في المتصفح وتنبيه المستخدم بشريط دائم متحرك عند تصفح التطبيق أو المتجر في بيئات المعارض أو مستودعات التخزين الضعيفة التغطية، مع حفظ البيانات محلياً وإعدادها للمزامنة التلقائية بمجرد عودة الاتصال.
11. **تأمين قنوات الاتصال والـ Webhooks**: إدماج مكتبة تدقيق وبصمات من خلال `security.ts` لحساب HMAC SHA-256 لتجنيب التجار الهجمات الاحتيالية في حالة ربط المتجر ببوابات المطورين أو تلقي طلبات مشوهة.

## 🌐 دليل التنفيذ العملي لإضافة القنوات المختلفة (Social Channels API Integration Guide)

يحتوي هذا الدليل على الإرشادات والواجهات البرمجية الأساسية لتسريع تكامل القنوات الاجتماعية لخدمة التلقي الآلي وتفصيل الطلبات:

### 📊 جدول واجهات برمجة التطبيقات (APIs) الأساسية لكل قناة وبوابات استقبال الخادم في `server.ts`

| القناة | 🌐 واجهة برمجة التطبيقات (API) الرئيسية | طريقة الربط الأساسية | مسارات استقبال الخادم في `server.ts` |
| :--- | :--- | :--- | :--- |
| **فيسبوك ماسنجر** | Messenger Platform API | HTTP Webhook POST | `/api/webhooks/facebook` |
| **إنستغرام** | Instagram Graph API | Webhooks Facebook Client | `/api/webhooks/instagram` |
| **واتساب** | WhatsApp Business API | Webhooks Meta / Twilio | `/api/webhooks/whatsapp` |
| **تيليغرام** | Telegram Bot API | Webhooks Telegram Bot | `/api/webhooks/telegram` |
| **بوابة الماستر الموحدة**| Unified Aggregator Webhook | Combined Webhook Router | `/api/webhooks/master` |

---

### 🚀 خطوات تفعيل قنوات الاستقبال الآلي وتدفق البيانات:

1. **إعداد تطبيق المطورين (Meta Developer / Telegram BotFather)**: 
   - إنشاء تطبيق تجاري وتفعيل ميزات التراسل (Messaging) للوصول إلى مفاتيح الاتصال وسلسلة التحقق (Access Tokens & Verify Tokens).
2. **برمجة رابط الاستقبال الخفي (Webhook Endpoint / Server-side Webhook)**:
   - إنشاء مدخل استقبال مخصص في `server.ts` لاستقبال إشارات التراسل الفورية بتنسيق JSON وتأكيد الرد السريع.
3. **التمرير لذكاء المنصة (AI Dispatching and Pipeline)**:
   - بمجرد قراءة محتوى الرسالة، يتم توجيه الرسالة والمحادثة مباشرة لنموذج الذكاء الاصطناعي (Gemini SDK) لتصنيفها، تتبعها، واستخلاص تفاصيل المشتري والولاية تلقائياً وترجمتها فورياً إلى الفرنسية.
